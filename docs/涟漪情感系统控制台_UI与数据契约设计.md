# 涟漪情感系统：控制台 UI 与数据契约设计

版本：0.1（设计确认稿）  
状态：只用于设计确认，尚未进入界面改造

## 1. 设计定位

“涟漪情感系统”是莲心的实时情绪观察、解释和调试界面，不承担长期记忆浏览职责。

- 记忆星图：浏览记忆对象、记忆情节、长期故事线及其来源关系。
- 涟漪情感系统：观察五轴状态、关系状态、变化原因、回复指导和主动动机。

界面不再使用没有明确语义的星体位置、星体大小或装饰性运动。所有图形都必须能回答“代表什么、为什么变化、如何操作”。

## 2. 中文术语规范

代码字段保持兼容，用户界面统一使用以下中文名称：

| 内部术语/字段 | 用户界面名称 | 含义 |
|---|---|---|
| Saga | 长期故事线 | 跨越多个记忆情节的长期经历，对情绪基线产生轻微影响 |
| Episode | 记忆情节 | 一组相关记忆片段整理出的短篇叙事 |
| Entity | 记忆对象 | 人物、地点、事件、项目或兴趣等可识别对象 |
| Fragment | 记忆片段 | 从单条或少量对话中提取的事实 |
| baseline bias | 情绪基线偏置 | 长期故事线对五轴状态的缓慢拉动 |
| motive | 当前主动动机 | 当前状态下更倾向观察、联系、自我调节或保持平静的原因 |
| appraisal | 对话情绪评估 | 对当前用户消息进行的情绪变化判断 |
| drift | 时间漂移 | 没有新消息时，状态随时间产生的自然变化 |

“长期故事线”是唯一对用户展示的名称，代码中的 `saga` 只作为内部兼容字段保留。

### 3.1 顶部状态栏

固定展示：

- 产品名称：涟漪情感系统。
- 当前人格和当前用户。
- 同步状态：实时、暂停、连接异常。
- 最近更新时间。
- 设置入口和帮助入口。

### 3.2 左侧五轴区

五轴区是主视觉，不使用星体图。每一行包含：名称、进度条、当前值、变化速度、趋势箭头和阈值标记。

### 3.3 中央解释区

中央区回答“莲心现在是什么状态、为什么是这个状态”：

- 当前情绪集群。
- 关系阶段和关系分数。
- 当前主动动机及原因。
- 当前回复语气指导。
- 实时对话、时间漂移、长期故事线三类影响的贡献比例。

### 3.4 右侧状态事件流

按时间倒序显示最近事件。事件内容必须包含时间、来源、变化轴、变化量和可读原因。点击事件打开详情，不跳转到无关页面。

### 3.5 底部操作栏

底部操作只放低风险、高频操作：暂停/恢复刷新、三种模拟场景、撤销模拟。所有模拟按钮必须有“仅调试，不触发外部行动”的提示。

## 4. 五轴数据展示规范

| 轴 | 范围 | 用户解释 | 关键阈值 |
|---|---:|---|---|
| 连接需求 | 0~1 | 有多想联系用户 | 观察、考虑联系、主动联系 |
| 防御感 | -1~1 | 回复时有多谨慎或戒备 | 谨慎回复、关系修复 |
| 情绪基调（内部 `valence`） | -1~1 | 当前情绪偏正面还是负面 | 低落、平稳、愉快 |
| 唤醒度 | -1~1 | 平静、兴奋、焦虑或躁动程度 | 高唤醒调节 |
| 沉浸度 | 0~1 | 对当前任务、活动或话题的投入程度 | 活动保持、沉浸衰减 |

每个轴应提供以下字段：

- `value`：当前值。
- `normalized`：用于绘制进度条的 0~1 值。
- `delta`：最近一次事件带来的变化。
- `trend`：`up`、`down` 或 `steady`。
- `velocity`：单位时间变化速度。
- `thresholds`：该轴相关阈值。
- `source`：最近一次主要影响来源。

## 7. 交互模式

### 实时模式

默认模式。显示当前状态和最近事件，不修改数据。

### 历史模式

显示时间轴和历史状态。拖动时间轴只改变查看结果，不改变真实状态。

### 模拟模式

允许执行温暖回应、冷淡回应、模拟等待、完成任务、自我调节等场景。模拟开始时保存状态快照，支持一键撤销。模拟不会触发主动聊天、工具调用或外部平台消息。

## 8. 设置面板

### 简易设置

- 情感系统启用/停用。
- 是否启用长期故事线影响。
- 长期故事影响强度：弱、标准、强。
- 是否允许情绪动机参与主动调度。
- 事件日志保留数量。

### 高级设置

- 连接需求增长率。
- 观察、考虑联系、主动联系阈值。
- 愉悦度、唤醒度、防御感回归速度。
- 沉浸度衰减速度。
- 长期故事线偏置最大幅度。

### 调试设置

- 语义分析模式。
- 显著事件阈值。
- 模拟事件是否写入历史。
- 是否显示详细来源。
- 清除模拟事件。

## 9. 视觉和性能规范

- 深黑蓝底色，青蓝为主色，紫红表示负向变化，橙色表示阈值警告。
- 正文不小于 11px，事件流不小于 12px，标题 14~16px。
- 进度条允许平滑变化，不使用持续闪烁或无意义呼吸动画。
- 状态变化只进行一次短暂高亮。
- 不使用没有数据语义的星体布局。
- 页面渲染只接收快照，不在 JavaScript 中查询数据库。
- 快照生成与 UI 绘制解耦，刷新不能阻塞聊天主线程。
- 目标：状态更新后 150ms 内完成 UI 重绘，普通状态查看不触发 LLM 调用。

## 10. 分阶段实施与验收

### 阶段一：后端观测数据

补充轴趋势、阈值、变化来源、长期故事线贡献和事件解释；保持旧字段兼容。

### 阶段二：静态控制台界面

先实现实时模式，移除无语义星体，完成五轴条、中央解释区和事件流。

### 阶段三：交互与设置

加入历史模式、模拟模式、撤销、设置抽屉和帮助说明。

### 阶段四：性能与稳定性

验证多人格、多会话、长时间运行、窗口反复打开关闭、无闪烁和刷新延迟。

验收标准：

- 用户 5 秒内能理解五轴含义。
- 每个状态变化都能找到至少一个原因。
- 每个按钮都有明确反馈和可撤销路径。
- 实时更新不阻塞聊天。
- 不增加 LLM 调用次数。
- 不影响工具权限、记忆检索和主动调度。

## 11. 明确不做的事情

- 不把记忆星图和涟漪情感系统合并成一个混杂页面。
- 不把底层数据库字段直接堆到用户界面。
- 不提供会绕过安全策略的情绪强制按钮。
- 不用动画掩盖没有解释的数据。
- 不在没有测试和回滚机制的情况下允许模拟状态影响真实主动行为。
